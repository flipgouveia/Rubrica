# Fixtures corpus

The test corpus described in `agents/CONTRACTS.md` §9. Every engine feature is expected to
have tests against this corpus, and the portability gate (§9 / `docs/ARCHITECTURE.md`) applies
to anything Rubrica writes: output must re-open in a fresh PDFium instance *and* parse with
pdf-lib (see `scripts/verify-pdf.mjs` — the pdf-lib half only; the PDFium half is a Rust-side
concern owned separately).

All generation is deterministic — no timestamps, no randomness — so regenerating the corpus
never produces a spurious diff.

## The fixtures

- **`text.pdf`** — a 3-page, text-first document: real paragraphs of original English body
  text (a fictional "Rubrica Field Guide") with section headings, the kind of thing someone
  would actually open, scroll, search, and select text in. This is also the source document
  for `corrupt.pdf` and `encrypted.pdf` below.
- **`unicode.pdf`** — a single page of original Portuguese (PT-PT) prose with full European
  Portuguese accent coverage (ção, ã, õ, ê, á, à, ç, â, í, ó, ú, …) plus non-ASCII punctuation:
  an em dash (—) and curly single/double quotes (‘ ’ “ ”). Stresses text extraction/rendering
  beyond plain ASCII.
- **`500-page.pdf`** — exactly 500 pages, each with a single "Page N of 500" label and nothing
  else. Exists purely to stress-test tiling/virtualization performance work later; content
  richness is deliberately not the point, so generation stays fast (~106 KB total).
- **`form.pdf`** — a real-ish government-style AcroForm, "Formulário de Identificação", with
  one of each field kind pdf-lib supports: two text fields (Nome completo, Data de nascimento),
  a radio group (Estado civil, 4 options), a dropdown (Distrito, 8 options), and a checkbox
  (Aceito os termos e condições).
- **`scanned.pdf`** — a single page that is *only* an embedded raster image — no text objects,
  no fonts, no text layer whatsoever. Simulates a scanned document: PDFium has nothing to
  select or search here by design. The source raster (`scanned-source.png`, a faux ~200dpi
  1700×2200 "page" built from flat-color bands standing in for lines of printed text) is
  generated by the dependency-free `gen-scanned-source.py` and committed, so building
  `scanned.pdf` via `pnpm fixtures:generate` never needs Python at generation time.
- **`encrypted.pdf`** — `text.pdf`'s content, password-protected. pdf-lib cannot write PDF
  encryption, so this is produced separately by `gen-encrypted.py` using pypdf. Both the user
  password (required to open the file) and the owner password (required to change permissions)
  are set to **`rubrica-test`**, using AES-256 (PDF 2.0 / R6) encryption. A non-empty *user*
  password is what actually exercises Rubrica's `ENCRYPTED` error path — a document with only
  an owner password set opens without a prompt in essentially every reader, which would defeat
  the point of this fixture.
- **`corrupt.pdf`** — `text.pdf`, truncated to 35% of its original byte length. The cut lands
  well after the header and several complete indirect objects (catalog, pages tree, part of the
  content stream), so a naive byte-level scan gets a good way into the file before running out —
  but there is no xref table, no trailer, and no `%%EOF`, and the file also ends mid-object
  rather than on a clean object boundary. pdf-lib's loader has no trailer to find the document
  root from, and its xref-recovery scan cannot rebuild a usable structure from a stream that
  cuts off mid-object either, so `PDFDocument.load()` reliably throws
  (`Failed to parse PDF document ... Failed to parse invalid PDF object`). Verified empirically
  when the corpus was built, not just asserted — see `fixtures/generate.mjs`'s
  `generateCorruptPdf()` for the exact byte math.
- **`fixtures/smoke/tiny.pdf`** — a separate, hand-built 2-page fixture for the Rust pdfium
  smoke test (`src-tauri/tests/pdfium_smoke.rs`). Not touched by anything in this directory;
  generated by `scripts/gen-smoke-fixture.py` (R1, pre-existing).

## `book.pdf` — ground truth for search v2

`book.pdf` is a 40-page pt-PT "Manual de Contratos" (US Letter, Helvetica, deterministic filler
from a seeded PRNG) used to test proximity search, scope by chapter, header/footer exclusion and
accent-insensitive matching (`agents/SEARCH-ORCHESTRATION.md` §2). Three files come out of
`pnpm fixtures:generate`:

- **`book.pdf`** — the document, with a real hand-built `/Outlines` tree (5 chapters, 12 sub-entries,
  one depth-2 entry; 18 entries, destinations `/XYZ`).
- **`book-no-outline.pdf`** — the same pages with no `/Outlines` (scope-by-chapter must be disabled).
- **`book.expected.json`** — the **source of truth for tests**. It is computed by the generator
  from the exact strings it draws (never tallied by hand): outline (`page`/`pageEnd` 0-based
  inclusive, `depth`), header and footer rules, per-page whole-word `contrato` counts, and every
  controlled zone below. Tests must read this file instead of hard-coding numbers.
  `src-tauri/tests/book_fixture.rs` checks that PDFium's extraction agrees with it.

Page layout: page 1 is a title page (no header or footer). Pages 2-40 have a running header at
baseline y=752 (top 8 % band: even pages "Manual de Contratos", odd pages the current top-level
chapter title) and a footer `Página N de 40` at baseline y=30. Body text is 11 pt between y=712
and y=96. Chapters start on a new page; sub-entries may start mid-page (outline `Dest` = the
heading line). Pages 35-37 are intentionally short (see decoys).

The words `rescisão`, `prazo`, `indemnização` and the standalone `ação` never occur outside the
controlled zones (`rescisão`/`indemnização`/`prazo` are not in the filler vocabulary; the chapter
is "Cessação" and the title "4 Prazos e notificações" only has the plural). The unaccented `acao`
never occurs. Whole-word lowercase `contrato` occurs 189 times in body text (see `contrato.byPage`;
the hyphen-split `contra-`/`to` is not counted); titles/headers that contain it (chapters 2 and 3
and their odd-page running headers) are counted separately in `contratoInTitles`. Standalone
`ação` is only guaranteed with whole-word matching: longer words ending in `-ação` are everywhere.

Controlled zones (1-based pages in this list; the JSON uses 0-based `page` plus `pageLabel`):

| Zone | Page | Purpose |
| --- | --- | --- |
| `tightTrio` | 17 | `rescisão`, `prazo`, `indemnização` within 125 chars. Found with a 250/500-char window, not with 100. |
| `looseTrio` | 30 | Same three words spread over 386 chars across 5 lines. Found with 500, not with 250. |
| `decoy` | 34, 38 | `rescisão` on p.34 and `indemnização` on p.38, each alone. Pages 35-37 are short so the two terms are only ~3,560 chars apart (`decoy.charsBetween`): a 5000-char window across pages joins them, a 500-char one does not. |
| `crossPage` | 22-23 | Last body line of p.22 ends `... a parte que pretenda fazer cessar`, first body line of p.23 starts `o acordo deve comunicá-lo ...` (phrase "fazer cessar o acordo" spans the page break, with footer and header in between). |
| `hyphenated` | 25 | `contra-` / `to` (the word "contrato" split by a hard hyphen) and `pré-` / `aviso` (a real compound). Matching must accept both forms. |
| `softHyphen` | 26 | A line ending `obriga` + U+00AD, next line `ções ...`. |
| `ligatures` | 27 | `eﬁcácia` and `ﬂuxo` drawn with real fi/fl glyphs: a second Helvetica font dictionary (`/Encoding` with `/Differences [128 /fi 129 /fl]`) and raw `Tj` operators, since WinAnsi has no U+FB01/U+FB02. |
| `quotesNbsp` | 18 | `“justa causa”` (U+201C/U+201D) and `art.` + U+00A0 + `12.º`. |

What PDFium actually extracts for the tricky ones (measured by `book_fixture.rs`, pdfium-render
0.9 on the vendored build):

- **Line-end hyphens** (hard `-` and the soft hyphen U+00AD alike): `text.all()` returns
  `contra` + **U+0002** + `to` — the hyphen is replaced by the control character U+0002 and
  **no line break is emitted**. The per-char API gives the same U+0002 with `is_hyphen() == true`.
  A matcher has to treat U+0002 as the line-end hyphen marker.
- **Ligatures**: expanded to the plain letters (`fi`, `fl`), two chars sharing one box.
- **NBSP**: comes back as a plain U+0020.
- **Curly quotes**: kept as U+201C / U+201D.

## Regenerating the corpus

Most of the corpus is pure Node + pdf-lib and rebuilds with one command from the repo root:

```sh
pnpm fixtures:generate      # runs node fixtures/generate.mjs
```

This (re)writes `text.pdf`, `unicode.pdf`, `500-page.pdf`, `form.pdf`, `scanned.pdf`, and
`corrupt.pdf`, plus `book.pdf`, `book-no-outline.pdf` and `book.expected.json`. It reads `scanned-source.png` rather than regenerating it — see below if you
need to change the source image itself.

Two fixtures need a one-off manual step instead, and are committed as binaries rather than
built on every install (the same treatment as `pdfium.dll` elsewhere in this repo):

**`encrypted.pdf`** — needs pypdf (MIT, pure Python) plus `cryptography` (backs its AES-256
implementation):

```sh
pip install pypdf cryptography     # one-time
python fixtures/gen-encrypted.py   # regenerate whenever text.pdf's content changes
```

**`scanned-source.png`** — needs nothing beyond the Python standard library (same
struct+zlib-by-hand technique as `scripts/gen-placeholder-icon.py`); only re-run this if you
want to change what the simulated scan looks like:

```sh
python fixtures/gen-scanned-source.py fixtures/scanned-source.png
```

## Verifying the corpus

```sh
pnpm verify:pdf              # checks every fixtures/*.pdf (corrupt/encrypted reported as skipped)
pnpm verify:pdf path/to.pdf  # checks specific file(s); no skip list applies to explicit args
```

This runs the pdf-lib half of the portability gate only (see `scripts/verify-pdf.mjs`'s header
comment) — it does not re-open output in PDFium. That half belongs to whichever engine agent
wires up the Rust-side PDFium round-trip test.
